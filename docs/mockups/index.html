Comment ça marche ?

1Chaque action est écrite immédiatement sur le téléphone et ajoutée à la file (PENDING).
2Au retour du réseau, la file part vers le webhook Google Apps Script.
3Apps Script insère ou met à jour la ligne grâce à l'ID unique, puis confirme chaque item (SYNCED).
4En cas d'échec, l'item passe en ERROR avec un message lisible et un compteur de tentatives.

4 · Synchro — file d'attente transparenteSuccès partiel : un refus serveur ne bloque pas les autres lignes

À propos de ces maquettes. Elles décrivent le comportement cible de l'application Flutter livrée dans app/ : mêmes libellés, mêmes couleurs sémantiques, même hiérarchie. Les seuls écarts assumés sont ceux du rendu navigateur (police système au lieu de Roboto, absence d'animations). Voir aussi : docs/01-ARCHITECTURE.md, docs/02-DATA-MODEL.md, docs/03-SYNC-PROTOCOL.md.
